# 04 · 资源占用预算

> **这是 Chit 全项目最重要的一份文档。** 用户的硬要求「没存任何文本时挂后台不得超过 10 KB」在这里被正面回答。
> 接手 Agent 如果只读一份文档，读这份。

---

## 一、先把「10 KB」这句话说清楚

用户的要求原文是：

> 「如果本身里面没有存任何文本，挂在后台必须不能多于 10KB，就问你能不能做到？我说这里面没有存任何文本的情况下。」

**答案是：能做到，但必须先把「内存」这个词拆成三个口径。** 混在一起谈，会得出一个既错误又无法验收的结论。

| 口径 | 它是什么 | 怎么看它 | 10 KB 能不能做到 |
| --- | --- | --- | --- |
| **A. 进程总工作集** | 任务管理器「内存」列的那个数字 | 任务管理器 → 详细信息 → 工作集 | **不能。物理上不可能。** |
| **B. 进程私有工作集** | 该进程私有提交的那部分 | 任务管理器 → 详细信息 → 私有工作集 | **不能。** 真实下限在数百 KB |
| **C. 应用自身堆分配** | Chit 自己的数据结构吃掉的内存 | 需要专门的检测工具 | **能。可以压到 10 KB 以内** |

### 1.1 为什么 A 和 B 不可能

**任何一个真实的 Windows 进程，只要它跑起来，操作系统就会替它映射一组系统库**——`ntdll.dll`、`kernel32.dll`、`user32.dll`、`gdi32.dll`、`combase.dll` 等等。这些不是 Chit 申请的，是「进程存在」这件事本身的开销。此外每个线程还要提交一段栈（默认提交 4 KB 起，保留 1 MB）。

哪怕程序主体只有一行 `return 0;`，任务管理器里也会显示 1 MB 以上。**10 KB 连 `ntdll.dll` 的一个内存节都装不下。**

所以「挂后台 ≤ 10 KB」这句话，在口径 A 和口径 B 下**没有任何一款真实软件能做到**，无论用什么语言、什么框架。这不是我们的工程能力问题，是 Windows 的进程模型决定的。

### 1.2 口径 C 是可以承诺的

如果「10 KB」指的是 **Chit 自己申请的那部分内存**（文本模型、撤销栈、编码检测状态、标签页结构、配置缓存），那么在**空文档**状态下，这个数字可以压到 10 KB 以内：

| 数据结构 | 空文档时的占用 |
| --- | --- |
| 文本模型（空 buffer 的初始块） | ≈ 1–4 KB |
| 标签页描述（一个 Tab 的元数据） | ≈ 200 B |
| 撤销栈（空） | ≈ 100 B |
| 编码 / 换行符状态（一个枚举 + BOM 标志） | ≈ 16 B |
| 配置缓存（ini 解析结果） | ≈ 1–2 KB |
| **合计** | **≈ 2.5–6 KB，目标 ≤ 10 KB** |

**这一条是可测、可承诺、可写进验收标准的。**

## 二、真正的答案：不常驻，后台占用 0 KB

上面是分账。但比「分账」更彻底的办法是**让这个进程根本不存在**。

**Chit 的默认形态是零常驻：**

- 关闭窗口 = 进程完全退出。任务管理器里立刻消失。
- 不驻留托盘、不注册服务、不装驱动、不写开机启动项、不留后台线程、不留隐藏窗口。
- 因此「挂在后台」这个状态**根本不存在**，后台内存是 **0 KB**。

**0 ≤ 10 KB，严格成立。** 而且是永久成立：不随版本变化、不随打开过的文本量变化、不随使用时长变化。这比「压到 10 KB 以内」更彻底——**它连一个可以被测量的对象都没有。**

用户想要的三件事，用「不常驻」一次全部满足：

| 用户的要求 | 零常驻如何满足 |
| --- | --- |
| 「挂在后台都不会有人注意到它」 | 后台根本没有它 |
| 「挂后台自启动都完全没有影响」 | 它不写启动项，所以「自启动」这件事不存在，影响是 0 |
| 「没存任何文本时挂后台不得超过 10KB」 | 后台占用 0 KB |

**代价只有一个：每次打开是冷启动。** 而原生 Win32 程序的冷启动在 100 ms 以内（见第五节预算），用户感知上就是「点一下就开了」，与常驻没有区别。

## 三、可选档：预热常驻（默认关闭）

有些人会想要「更快」，希望托盘里常驻一个预热进程。我们提供这个开关，**但默认关闭，并且诚实地把代价写在设置项旁边**：

| 形态 | 后台内存 | 启动速度 | 说明 |
| --- | --- | --- | --- |
| **零常驻（默认）** | **0 KB** | 冷启动 < 100 ms | 推荐。没有任何后台痕迹 |
| 预热常驻（手动开启） | 私有工作集约 **1.2–2.0 MB**，工作集约 2–4 MB | 热启动 < 30 ms | 省下 70 ms，换来 1.5 MB 常驻 |

**这一档做不到 10 KB。任何真实进程都做不到。** 所以：

- 如果「≤ 10 KB」是不可谈判的硬指标 → **必须选零常驻**，这也是我们的默认值。
- 如果用户愿意接受 1.5 MB 换 70 ms → 可以在设置里打开，设置项文案必须写明「开启后会在托盘保留一个进程，占用约 1.5 MB」。

**这个开关同样必须满足：关闭它 = 进程立刻退出 = 托盘图标立刻消失 = 启动项被删除。**

## 四、磁盘预算

| 项 | 预算 | 说明 |
| --- | --- | --- |
| 主程序 `Chit.exe` | ≤ 800 KB | 底座约 300 KB，加上我们的功能后留出余量 |
| 内嵌图标与资源 | ≤ 200 KB | 进 exe 资源节，不散落文件 |
| 可选拼写词典 | ≤ 1 MB | **默认不安装**，用户主动启用才下载/释放 |
| 卸载器 | ≤ 100 KB | |
| 配置与许可证文件 | ≤ 100 KB | 底座版权声明必须随包 |
| **安装后合计** | **≤ 3 MB** | 比软件清单里写的 5 MB 更严 |

> 澄清一句：老清单里写过「这一条按 5MB 写死在物理上做不到」，那是针对**常驻内存**说的（见第一节），不是针对磁盘。**磁盘 3 MB 完全做得到。**

**绿色版：** 同时提供一个免安装 zip（解压即用、不写注册表、不建关联），体积约 1 MB。用户可以只用绿色版，这是「不是流氓软件」的最终证明。

## 五、运行时预算

### 5.1 内存

| 场景 | 私有工作集目标 | 说明 |
| --- | --- | --- |
| 空文档（窗口开着） | ≤ 2 MB | 主要是 OS 映射的库，不是我们的数据 |
| 1 MB 文本 | ≤ 6 MB | |
| 10 MB 文本 | ≤ 20 MB | |
| 100 MB 文本 | ≤ 200 MB | 走大文件模式，不全量建索引 |
| 1 GB 文本 | 只载入视口窗口 ± N MB | 见 [docs/02](docs/02-功能规格.md) 大文件模式 |
| **空文档时「应用自身堆分配」** | **≤ 10 KB** | 口径 C，见第一节 |

### 5.2 冷启动

| 阶段 | 目标 |
| --- | --- |
| 进程创建 → 窗口可见 | ≤ 60 ms |
| 窗口可见 → 可输入 | ≤ 100 ms |
| 打开 1 MB 文本 | ≤ 150 ms |
| 打开 100 MB 文本 | 先出窗口，后台载入并显示进度 |

**达到这个目标的前提（不可违反）：**

- 无 WebView、无 Electron、无 Tauri、无 .NET、无 JIT 预热。
- 不在启动路径上读配置以外的任何文件。
- 不在启动路径上加载词典、字体、图标主题、语言包。
- 不在启动路径上做任何磁盘扫描。

### 5.3 线程

| 项 | 预算 |
| --- | --- |
| 空文档时的线程数 | ≤ 4（主线程 + 消息循环相关） |
| 大文件载入时的后台线程 | ≤ 2，载入完成即退出 |
| 常驻线程 | **0** |

## 六、怎么测（可复现）

每次发版前，把下面四个数字测出来，写进 `CHANGELOG`。**没测过就不算做完。**

**① 后台占用（核心指标）**

```powershell
# 关闭 Chit 后执行，期望输出为空
Get-Process -Name Chit -ErrorAction SilentlyContinue
```

**② 空文档运行内存**

```powershell
# 打开 Chit 但不输入任何字符，然后执行
Get-Process -Name Chit | Select-Object WorkingSet64, PrivateMemorySize64
```

**③ 冷启动耗时**

```powershell
1..10 | ForEach-Object {
  $t = Measure-Command { Start-Process 'Chit.exe' -PassThru | Wait-Process }
  [math]::Round($t.TotalMilliseconds)
}
# 取中位数，期望 ≤ 100
```

**④ 安装体积**

```powershell
'{0:N2} MB' -f ((Get-ChildItem 'C:\Program Files\Chit' -Recurse -File |
  Measure-Object -Property Length -Sum).Sum / 1MB)
```

**⑤ 零联网验证**

用 Windows 防火墙出站规则或 Fiddler / Wireshark 挂一周，**期望记录数为 0**。

## 七、超预算了怎么办

按下面的顺序砍，**不许跳步**：

1. 砍可选功能：拼写检查 → 会话恢复 → 深色模式 → 语法高亮。
2. 砍视觉装饰：动画 → 自定义主题 → 图标主题。
3. 砍便利功能：最近文件列表 → 标签页拖拽重排 → 分屏。
4. **绝不砍这三样：冷启动速度、文本模型正确性、零常驻。**

**红线：任何一项改动如果让第 4 条里的任何一条退步，一律回退，不管功能多好。**
