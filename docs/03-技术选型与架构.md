# 03 · 技术选型与架构

> 小方工作室 · Chit ｜ 立项阶段 ｜ 2026-10-06
> 一句话原则：**没有任何运行时。程序就是那个 exe。**

---

## 一、选型的唯一标准

Chit 的技术选型不看「开发效率」，不看「生态丰富」，只看三个数字：

1. **冷启动多少毫秒。**
2. **安装后多少 KB。**
3. **关闭后还剩几个进程（必须是 0）。**

任何一项技术，只要在这三条上拖后腿，不管多好用，一律不要。

## 二、路线选择

### 2.1 首选路线：Notepad4 底座改造

| 项 | 内容 |
| --- | --- |
| 项目 | **Notepad4**（含上游 Notepad2 / Scintilla） |
| 语言 | C++ / Win32 API |
| 许可 | **BSD-3-Clause**（Notepad4、Notepad2）；**HPND**（Scintilla，BSD 系宽松） |
| 体积 | 单 exe，约 300 KB |
| 启动 | 30 ms 量级 |
| 已具备 | 多标签、编码识别、换行符切换、大文件、正则替换、行号、自动换行、拖拽打开 |

**为什么选它：** 它在功能上已经覆盖了 Chit 目标功能的 80%，而且它的体积与启动速度正好是我们要的。改造它的工作量，比自己从零写一个 Win32 文本编辑器小一个数量级。

**改造策略（重要）：**

1. **减法优先。** 先把它里面「不由用户掌控」的行为砍掉——任何自动更新、任何联网、任何遥测、任何捆绑、任何托盘常驻、任何开机自启。
2. **配置式改造优先。** 改资源、改字符串、改菜单、改默认值、删功能模块。**尽量不动核心编辑逻辑。**
3. **只在必要时重构。** 编码转换的有损保护、原子写入、大文件模式的进度提示，这几处需要我们自己写。

**必须做的三件改造：**

- **默认不常驻。** 底座中若有「保留在托盘 / 后台」相关逻辑，全部改为默认关闭并明确暴露开关。
- **拿默认打开权改走合规路径。** 底座原有的「替换记事本」实现如果走 IFEO 重定向，必须改为 [docs/06](06-文件关联与系统集成.md) 的合规方案。
- **执行文件与产品标识改名。** `Chit.exe`、窗口类名、注册表 ProgID、配置文件名全部换掉，不与他人冲突。

**必须保留的：** 底座与 Scintilla 的版权声明、许可证原文（放 `licenses/` 目录，随安装包分发）。

### 2.2 备选路线：Rust + windows-rs 自研

| 项 | 内容 |
| --- | --- |
| 语言 | Rust（`windows-rs` 直连 Win32 API） |
| 运行时 | **无**（no_std 不需要，但绝不引入 tokio / 异步运行时 / Web 框架） |
| 编辑控件 | 自研视口渲染，或绑定 Scintilla |
| 体积 | 单 exe，静态 CRT，约 500 KB–1 MB |
| 启动 | 50–90 ms |

**什么时候走这条路：** 如果 Notepad4 的改造被证明「越改越乱」，或者用户希望仓库是单一语言、单一许可（纯 MIT）。

**代价：** 大文件模式、编码探测、正则引擎都要自己写，工作量显著更大。

### 2.3 明确排除

| 技术 | 排除原因 |
| --- | --- |
| Electron | 100 MB 起步，冷启动 1 秒级，与需求正面冲突 |
| Tauri | 要带 WebView2 运行时，冷启动 300 ms 级，体积 10 MB 级 |
| WebView2 / 内嵌浏览器 | 同上，且引入系统组件依赖 |
| .NET / WPF / WinForms | 运行时依赖 + JIT 预热，冷启动与体积都不达标 |
| Qt | DLL 一堆，体积失控 |
| Java | JVM 启动即出局 |
| Python + PyInstaller | 打包后 10 MB 级，冷启动 500 ms 级，出局 |
| Flutter / Compose / MAUI | 均带运行时或虚拟机，出局 |

> 这份排除表不是偏好，是算术。**如果用户以后问「为什么不用 XXX」，答案在 [docs/04](04-资源占用预算.md) 第五节的预算里。**

## 三、分层架构

```
┌─────────────────────────────────────────────┐
│  外壳层（Win32）                              │
│  窗口 / 菜单 / 对话框 / 状态栏 / 标签栏         │
├─────────────────────────────────────────────┤
│  命令层（Command）                            │
│  所有动作走统一命令表：ID → 执行 → 快捷键 → 菜单 │
│  好处：菜单、快捷键、命令行三处共用一份定义        │
├─────────────────────────────────────────────┤
│  文档层（Document）                           │
│  文本模型 / 撤销栈 / 脏标记 / 编码状态 / 换行符   │
├─────────────────────────────────────────────┤
│  渲染层（Viewport）                           │
│  视口计算 / 行布局 / 绘制 / 大文件分块换入换出     │
├─────────────────────────────────────────────┤
│  平台层（Platform）                           │
│  文件 IO / 编码探测 / 剪切板 / 拖放 / 文件关联    │
└─────────────────────────────────────────────┘
```

**四条架构约束：**

1. **命令表是唯一的动作入口。** 界面上的任何动作，必须先在命令表里注册，再由菜单 / 快捷键 / 工具栏引用它。不许在消息处理里直接写业务逻辑。
2. **文档层不认识 Win32。** 文本模型不许出现任何 `HWND` / `HDC` / 消息类型，方便单测。
3. **启动路径必须可以画出调用链。** `WinMain` 到「窗口可输入」之间的调用链必须短到能画在一张纸上，任何新增的启动期工作都要经过评审。
4. **线程模型极简。** 主线程只做 UI。大文件载入与查找开**临时**后台线程，任务完成即退出。**没有任何常驻线程、没有线程池、没有定时器轮询。**

## 四、目录结构（改造自底座后的形态）

```

│   ├── doc/

│   │   ├── UndoStack.cpp        撤销栈

│   ├── platform/

│   │   ├── Assoc.cpp            文件关联（见 docs/06）
│   │   ├── Session.cpp          会话与草稿
│   │   └── Config.cpp           ini 读写
│   └── res/
│       ├── chit.rc              资源脚本
│       └── chit.ico
├── licenses/
│   ├── Notepad4-LICENSE.txt
│   ├── Notepad2-LICENSE.txt
│   └── Scintilla-LICENSE.txt
├── tests/
│   ├── encoding_test.cpp        编码探测与转换
```

## 五、关键实现要点

### 5.1 原子写入

```
1. 在同目录写 Chit.tmp.<pid>
2. 写入完成 → FlushFileBuffers
3. ReplaceFileW(原文件, 临时文件, 备份文件)
4. 成功后删除备份；失败则用备份还原
```

**绝不直接原地覆盖用户文件。** 断电容错、杀进程容错都靠这一步。

### 5.2 编码探测

按 [docs/02](02-功能规格.md) A3 的四步走。实现要求：

- 严格 UTF-8 校验必须走状态机，**不预先分配全文内存**（大文件流式校验）。
- GB18030 判定用「常用汉字区间命中率 + 无替换符」的启发式，阈值写进常量表，可调。
- 探测结果只是一个**建议**，保存时不改编码。

### 5.3 有损转换保护

转换为目标编码时，先做一次**试转换**：逐字符检查是否可表示，不可表示的位置收集成列表。若有，弹一次对话框列出前 20 处上下文，让用户确认。确认后才真正写盘。

### 5.4 大文件分块

- 维护一个块索引：`{偏移, 字节长度}` 数组，按换行扫描增量构建，扫描在后台线程做。
- 视口渲染只向块索引要「第 N 行开始的 K 行」。
- 内存里常驻的块窗口默认 ±4 MB，滚动时按 LRU 换出。
- 全文查找在后台线程顺序扫描并报告进度，可取消。

### 5.5 无网络验证

在 CI 或提交前，对源码做一次扫描：**禁止出现任何网络相关符号**。

```
socket / connect / WSAStartup / WinINet / WinHTTP / UrlMon / InternetOpen
curl / libcurl / http / https / TcpClient
```

发现任何一个，构建即失败。这是把「零联网」从承诺变成**编译期强制**。

## 六、构建与产物

| 项 | 要求 |
| --- | --- |
| 编译器和工具链 | MSVC / CMake（或 Rust / cargo） |
| CRT | **静态链接**，不依赖 VC++ 运行库 |
| 产物 | **单文件 `Chit.exe`**。安装包里除了 exe、许可证、可选词典，没有别的东西 |
| 优化 | 发布版开尺寸优化 + 链接期优化，符号剥离 |
| 架构 | x64（首版）；x86 可选 |
| 系统要求 | Windows 10 1809 及以上 |

| 零联网 | 源码符号扫描 + 防火墙监控 |
