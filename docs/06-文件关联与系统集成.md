# 06 · 文件关联与系统集成

> 小方工作室 · Chit ｜ 立项阶段 ｜ 2026-10-06
> 用户要求：**「必须保证它有一个通过这个软件默认打开的功能，所以说它绝对不能是流氓软件。」**
> 这一句话里的两个要求是**互相约束**的——既要有默认打开权，又不能用流氓手段拿到。这份文档就是解法。

---

## 一、先说清楚：为什么这件事是难点

在 Windows 10 和 Windows 11 上，**任何程序都不能由程序自己静默地把自己设成某类文件的默认打开方式**。

这是微软在 Win8 之后专门加的保护：文件类型的最终决定权存在

```
HKCU\Software\Microsoft\Windows\CurrentVersion\Explorer\FileExts\.txt\UserChoice
```

这个键里有一个 `Hash` 值，由**文件扩展名 + 用户 SID + ProgID + 系统时间戳**共同算出，算法不公开、且随系统更新变化。**伪造它需要逆向系统内部实现，属于明确的流氓行为，且 Windows 会在检测到篡改时把用户的选择重置并弹出提示。**

所以，市面上某些「一键设为默认」的软件，走的其实是：

| 流氓手段 | 为什么不做 |
| --- | --- |
| 伪造 `UserChoice` 的 Hash | 篡改系统数据，Windows 会重置并提示用户；技术上就是流氓 |
| 用 IFEO 重定向 `notepad.exe` | 劫持系统程序，影响所有调用记事本的软件；卸载不干净就是灾难 |
| 改 `HKEY_CLASSES_ROOT\txtfile` 的默认值 | 破坏系统类注册，影响面不可控 |
| 反复弹窗骚扰用户去点默认 | 骚扰也是一种流氓 |

**Chit 一条都不做。** 下面是我们做的方式。

---

## 二、合规方案：三件事，各自独立

### 2.1 第一件：注册为「打开方式」候选（安装时做，可回滚）

这是**唯一需要写注册表的部分**，而且全部写在 `HKCU`（当前用户）下，不碰 `HKLM`、不碰 `HKEY_CLASSES_ROOT`。

安装时为每个用户勾选的扩展名注册：

```
HKCU\Software\Classes\Chit.TextFile\shell\open\command
    = "C:\Program Files\Chit\Chit.exe" "%1"

HKCU\Software\Classes\Chit.TextFile\DefaultIcon
    = "C:\Program Files\Chit\Chit.exe",0

HKCU\Software\Classes\.txt\OpenWithProgids
    = Chit.TextFile   (REG_NONE 空值)

HKCU\Software\Classes\Applications\Chit.exe\shell\open\command
    = "C:\Program Files\Chit\Chit.exe" "%1"

HKCU\Software\Classes\Applications\Chit.exe\SupportedTypes
    = .txt, .log, ...   (每个勾选的扩展名一个空值)
```

**这一组键的效果只有一件事：让 Chit 出现在**

- 右键「打开方式 → 选择其他应用」的列表里
- 「设置 → 应用 → 默认应用 → 按文件类型选择」的下拉列表里

**它不会抢走任何默认权。** 用户原来用什么，还是用什么。

**回滚：** 卸载时或用户点「移除所有关联」时，把上述键**精确删除**（先判断值是不是我们写的，是才删）。`.txt\OpenWithProgids` 下只删我们自己那一项，**不动其他项**。

### 2.2 第二件：主动引导用户设默认（首次启动后，用户主动点）

在「工具 → 文件关联…」里给一个设置面板：

```
┌─ 文件关联 ────────────────────────────────────┐
│ 让 Chit 可以打开这些文件类型：                    │
│                                                │
│  ☑ .txt      纯文本                            │
│  ☑ .log      日志          [全选] [全不选]      │
│  ☐ .ini      配置                              │
│  ☐ .cfg  ☐ .csv  ☐ .json  ☐ .xml              │
│  ☐ .md   ☐ .sql  ☐ .yaml  ☐ .bat              │
│  ☐ 自定义扩展名： [__________]                 │
│                                                │
│  [ 应用 ]                                      │
│                                                │
│  ───────────────────────────────────────────   │
│  设为默认打开方式                               │
│  Windows 不允许程序自己设默认，需要你点一下。      │
│  [ 打开系统默认应用设置 ]                        │
│                                                │
│  ───────────────────────────────────────────   │
│  [ 移除全部关联并还原 ]                          │
└────────────────────────────────────────────────┘
```

- 「应用」= 按勾选写上面的注册表键（**只写 HKCU**）。
- 「打开系统默认应用设置」= 调 `ShellExecuteW(L"ms-settings:defaultapps")`，或更精确地调用系统 API `IApplicationAssociationRegistrationUI::LaunchAdvancedAssociationUI("Chit")`，**直接跳到 Chit 的默认应用设置页**。
- 全程如实告诉用户「Windows 不允许程序自己设默认，需要你点一下」。**这就是不流氓的体现：把限制明说，而不是用技术绕过。**

> 若系统 API 不可用（旧系统或策略限制），退化为打开系统设置页 + 显示一行图文指引。

### 2.3 第三件：让「双击就打开」真的能用

注册表做完之后，用户在系统设置里把 `.txt` 选成 Chit，双击任意 `.txt` 就会走：

```
explorer 调用  Chit.exe "%1"
```

Chit 必须正确处理：

| 情况 | 行为 |
| --- | --- |
| `Chit.exe "D:\a.txt"` | 打开该文件为标签 |
| `Chit.exe "D:\a.txt" "D:\b.txt"` | 开两个标签 |
| 路径带空格、带中文、带引号 | 正确解析 |
| 已有实例在运行 | 把文件送到已有实例**开新标签**，然后新进程立刻退出（单实例） |
| 文件不存在 / 无权限 / 被独占 | 中文提示，进程正常退出 |
| 路径是文件夹 | 提示「这是一个文件夹」 |

**「已有实例就把参数转发过去然后自己退出」这一条很重要**——否则双击十个文件就开十个窗口，用户马上就会卸载。

## 三、绝不做的（红线）

| 禁止项 | 说明 |
| --- | --- |
| **不伪造 `UserChoice` Hash** | 篡改系统数据，会被系统重置，属流氓 |
| **不写 IFEO 重定向 `notepad.exe`** | 劫持系统程序，影响所有依赖记事本的软件 |
| **不改 `HKEY_CLASSES_ROOT`** | 该 hive 是 `HKLM\Software\Classes` + `HKCU\Software\Classes` 的合并视图，直接写它会污染系统级注册 |
| **不写 `HKLM`** | 安装需要管理员时应只用于写 `Program Files`，不用于写关联键 |
| **不改系统文件、不改 `notepad.exe`** | |
| **不加系统级右键菜单** | 不加「用 Chit 打开」到所有文件的右键；只有在用户勾选关联的类型上，由系统正常出现 |
| **不弹窗骚扰** | 安装完成后只提示一次「可去系统设置设默认」，用户关掉就不再提 |
| **不静默写开机启动项** | 默认不写。设置里的「开机启动」默认关，且必须由用户主动勾选才写 `HKCU\...\Run` |

## 四、卸载：必须干净，且可验证

卸载流程（写在安装器的卸载逻辑里，不靠用户手动清）：

```
1. 删除 %ProgramFiles%\Chit\ 全部文件
2. 删除 HKCU\Software\Classes\Chit.TextFile            （整棵树）
3. 删除 HKCU\Software\Classes\Applications\Chit.exe    （整棵树）
4. 对每个我们注册过的扩展名：
      删除 HKCU\Software\Classes\<扩展名>\OpenWithProgids 下的 Chit.TextFile 值
                                        ↑ 只删自己那一项
5. 若用户设过 Chit 为默认：
      不伪造恢复！只提示「系统设置里 .txt 的默认程序已不是你原来的选择，
      请到系统设置里改回」——或者更好：记录安装时的原默认 ProgID
      （只读记录，不写回），卸载时在卸载完成页给出明文指引
6. 询问（不默认）是否删除 %APPDATA%\Chit 与 %LOCALAPPDATA%\Chit
7. 删除开始菜单快捷方式；删除卸载项本身
8. 删除桌面上我们创建的快捷方式（若有）
```

**「不伪造恢复默认」这一点要解释清楚：** 用户如果自己把 `.txt` 设成了 Chit，卸载时我们**不能**偷偷写回一个原值——写回 `UserChoice` 同样是篡改。正确做法是提示用户去系统设置里改。**宁可留一步手动，也不做一次篡改。**

**卸载后验证脚本（写进发版清单）：**

```powershell
# 期望：以下三项全部查不到
Test-Path "$env:ProgramFiles\Chit"
reg query "HKCU\Software\Classes\Chit.TextFile"
reg query "HKCU\Software\Classes\Applications\Chit.exe"

# 期望：OpenWithProgids 下查不到 Chit.TextFile
reg query "HKCU\Software\Classes\.txt\OpenWithProgids"

# 期望：Run 键里查不到 Chit
reg query "HKCU\Software\Microsoft\Windows\CurrentVersion\Run"

# 期望：没有进程
Get-Process -Name Chit -ErrorAction SilentlyContinue
```

## 五、绿色版（免安装）的集成方式

绿色版**默认不写任何注册表**。它提供：

- 一个按钮「**注册本机（绿色版）**」——功能等同安装版写 HKCU 关联键，只是路径指向绿色版所在目录。
- 一个按钮「**移除本机注册**」——精确回滚。
- 「**加入右键菜单**」的开关（默认关，只加用户勾选的类型）。
- 全部记录存在 exe 同目录的 `chit.ini` 里，**用户能看见**。

**绿色版是「不是流氓软件」的最终证明**：用户可以直接把文件夹删掉，系统里什么都不剩。

## 六、交付前系统集成自检

- [ ] `reg query` 能查到 `HKCU\Software\Classes\Chit.TextFile`（安装后）
- [ ] 右键任意 `.txt` →「打开方式」里能看到 Chit
- [ ] 系统「默认应用」里 `.txt` 的下拉里能看到 Chit
- [ ] `ms-settings:defaultapps` 引导按钮能正确打开
- [ ] 双击 `.txt` 能打开（前提是用户已在系统设置里选中 Chit）
- [ ] `Chit.exe a.txt b.txt` 开两个标签
- [ ] 二次启动不产生第二个窗口，文件转发到已有实例
- [ ] 没有任何 `HKLM` 写入
- [ ] 没有 IFEO 键：`HKLM\SOFTWARE\Microsoft\Windows NT\CurrentVersion\Image File Execution Options\notepad.exe` 不存在
- [ ] 没有 `HKEY_CLASSES_ROOT` 写入
- [ ] 卸载后第四节验证脚本全部通过
- [ ] `HKCU\...\Run` 里没有 Chit（除非用户主动开启开机启动）
- [ ] 绿色版在完全未注册的情况下能正常打开 / 编辑 / 保存
- [ ] 「关于」页里写明「本程序不联网、不收集任何数据」，且这句是真的
