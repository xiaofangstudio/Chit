# 01 · 立项规划书

> 小方工作室 · Chit ｜ 立项阶段 ｜ 2026-10-06

---

## 一、一句话定位

**Chit 是一台电脑上最快的记事本。打开就在，关掉就没了，后台一点痕迹都不留。**

它替代的对象非常明确：**Windows 自带的记事本**。它不是要和 VS Code、Sublime、Notepad++ 抢用户，它要做的是让用户在日常改一个 `.txt`、看一眼日志、贴一段临时文本的时候，**不需要启动一台「IDE」**。

---

## 二、为什么值得做

### 2.1 用户原话

用户在立项时给这个产品划了三条线，逐字记在这里，后续所有设计不得偏离：

> 「记住，这玩意是所有体量里面最小的。并且需要保证它有一个通过这个软件默认打开的功能，所以说它绝对不能是流氓软件。要多轻量有多轻量。」
>
> 「轻量到什么程度呢？功能已经能多到能让用户把 Windows 默认记事本丢到一旁。轻量到什么程度呢？它挂在后台都不会有人注意到它，甚至挂后台自启动都完全没有影响！完全没影响！如果本身里面没有存任何文本，挂在后台必须不能多于 10KB，就问你能不能做到？」

拆成四条硬要求：

1. **全家族体量最小。**
2. **必须能「用本软件默认打开」**（文件关联 / 设为默认）。
3. **绝对不能是流氓软件。**
4. **没存文本时，挂后台内存 ≤ 10 KB。**

第 4 条是本项目的核心技术命题，**在 [docs/04](docs/04-资源占用预算.md) 里有完整解答**，结论先写在这里：**能做，但要把话说准——用的办法是「不常驻」，后台占用 0 KB。**

### 2.2 真实的市场空缺

| 产品 | 问题 |
| --- | --- |
| Windows 记事本 | 太弱。没有多标签、没有编码切换（老版本连 UTF-8 无 BOM 都处理不好）、没有正则替换、大文件打不开、换行符不能切 |
| Notepad++ | 功能够，但装完几十 MB、GPL 许可（不能并入我们的 MIT 仓库）、带插件生态与自动更新、启动不够快 |
| Notepad4 / Notepad2 | 已经很接近目标，BSD-3 许可，**这就是我们的底座** |
| VS Code / Sublime | 太重。为了看一眼 txt 启动一个几百 MB 的编辑器，是荒谬的 |

**Chit 的位置：比记事本强得多，比任何编辑器都轻。** 底座直接用 Notepad4，在此基础上做减法（砍掉不由用户掌控的行为）和加法（补上中文用户真正需要的编码与换行处理）。

## 三、目标用户

- 开发者在改配置、看日志、临时贴一段 JSON / SQL / 正则。
- 普通用户双击一个 `.txt`、`.log`、`.csv`、`.ini`、`.md` 源文件。
- 需要处理中文编码的人（GBK ↔ UTF-8 互转、BOM 增减、CRLF ↔ LF 切换）。
- 对「后台一堆进程」极度敏感的人——**这是本项目最核心的目标用户画像**。

---

## 四、产品边界

### 4.1 Chit 做什么

- 纯文本的打开、编辑、保存、另存。
- 多标签、编码识别与切换、换行符切换。
- 查找替换（普通 / 正则 / 大小写 / 全词）。
- 撤销重做（无实际上限）。
- 行号、自动换行、缩进、行尾空白处理。
- 大文件模式（百 MB 级）。
- 会话恢复。
- 深色模式。
- 文件关联与默认打开。

### 4.2 Chit 明确不做

| 不做 | 为什么 | 谁来做 |
| --- | --- | --- |
| Markdown 渲染与预览 | 一渲染就要挂排版栈和图片解码，体积与内存立刻失控 | **Scheda** |
| 语法高亮全家桶 | 着色规则表会让体积和内存膨胀；纯文本工具不需要 | 交给 IDE 类产品 |
| 图片 / 表格 / PDF 查看 | 同上 | 交给系统或其他产品 |
| 插件系统 | 插件生态必然带来体积、启动开销与安全面 | 不做 |
| 云端同步 / 账号 | 一联网就不再是「不是流氓软件」 | 不做 |
| AI 写作 / AI 续写 | 产品线整体无 AI | 不做 |
| 多窗口 / 分屏 | 与「秒开 + 零常驻」哲学冲突，首版不做 | 后续再议 |
| 十六进制模式 | 与纯文本定位不符 | 交给专用工具 |
| 终端 / 编译 / 运行 | 这是 IDE 的活 | 不做 |

**判断准则：** 一个功能如果要在「启动速度」「磁盘体积」「后台占用」这三条里让任何一条退步，就必须先证明它值得，否则一律不做。

## 五、非流氓软件承诺书

用户点名要求「它绝对不能是流氓软件」。这一条**不是宣传语，是架构约束**。逐条列在这里，供后续所有版本对照检查：

| 承诺 | 落地方式 |
| --- | --- |
| 不联网 | 程序内没有任何网络调用代码。不遥测、不统计、不上报崩溃 |
| 不自动更新 | 不检查、不下载、不提示、不静默替换 |
| 不捆绑 | 安装包内只有 Chit 自己，无任何推荐软件、无工具栏、无「全家桶」 |
| 不劫持系统 | 不改写 `notepad.exe`、不动系统文件、不加系统级右键菜单 |
| 不偷偷改设置 | 除用户主动操作外，不修改任何系统或他人设置 |
| 可干净卸载 | 卸载后文件删净、关联删除、默认程序还给用户原选择、注册表无残留 |
| 拿默认权走官方路径 | 只注册 ProgID 与 OpenWith 候选，默认权引导用户在系统「默认应用」页面点选 |
| 所有行为可见 | 不做任何「用户不知道它在干什么」的事。程序里没有隐藏窗口、没有隐藏进程、没有隐藏计划任务 |
| 开源可审计 | MIT 交付，任何行为都能被代码对照 |

**任何一条被违反，这个产品就失去了存在的理由。**

## 六、与家族其他产品的关系

| 关系 | 说明 |
| --- | --- |
| 与 **Scheda** | 一对。Chit 管纯文本，Scheda 管带格式 Markdown 与图片。两者共用「零常驻 + 秒开」的哲学，界面观感尽量一致 |
| 与 **FangBox** | 分发渠道。Chit 通过 FangBox 与官网 MSI 分发，不自己做更新器 |
| 与 **Reelix / Strata / 其他** | 被当作**外部编辑器**调用。用户在那些软件里点「用外部程序打开」，能选中 Chit 即可，不需要任何 IPC 协议 |
| 与 **小方生产力官网** | 官网提供下载页与说明页，Chit 自己不带任何官网跳转按钮 |

## 七、成功判据

这个项目做完之后，用下面五条来判断是否成功。**任何一条不达标，就说明做偏了。**

1. 装完之后，用户把 `.txt` / `.log` / `.ini` 的默认打开方式设为 Chit，**并且三个星期后没有改回去**。
2. 任务管理器里，Chit 关闭之后**搜不到任何相关进程**。
3. 用 PowerShell 测冷启动，**中位数在 100 ms 以内**。
4. 安装目录总大小**在 3 MB 以内**。
5. 用代理或防火墙监控一周，Chit **零网络请求**。

## 八、明确的风险

| 风险 | 应对 |
| --- | --- |
| 底座 Notepad4 是 C++ 工程，改造门槛高于 Web 项目 | 优先做「配置式改造」（改资源、改行为、删功能），少动核心；必要时才重构模块 |
| 「零常驻」意味着每次都要冷启动，用户可能觉得慢 | 用冷启动速度硬扛。若实测超过 100 ms，先优化启动路径，**而不是**加常驻 |
| 10 KB 这个指标理解不一致 | 已在 [docs/04](docs/04-资源占用预算.md) 把三种口径讲清，避免后续验收扯皮 |
| 用户可能后续要求加功能 | 回到第 4.2 节的判断准则：先过「轻量三关」，再谈功能 |
| 拿默认打开权在 Windows 10/11 上有限制 | 已在 [docs/06](docs/06-文件关联与系统集成.md) 给出合规且可逆的具体方案 |
